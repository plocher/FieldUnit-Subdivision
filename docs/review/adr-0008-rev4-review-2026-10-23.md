# Adversarial review of ADR 0008 rev 4, 2026-10-23

An independent review by a fresh agent anchored on the sources of truth in their order of authority: FieldUnit
`docs/GLOSSARY.md`, FieldUnit ADR 0005 §4, Subdivision ADR 0009 (accepted 2026-10-23), the owner's rulings of
2026-10-23 (logical PanelColumn and ModelLamp; the Railroad symbol; the macro `<ROLE:KIND:Field>`; `Name` as identity;
CMRInet), then ADRs 0001, 0004, 0005 as amended. The reviewer was told what the owner had ruled out (hosts, the node as
a processor, topic roots in reference data, KiCad text variables, directories, bare references) and asked for one
findings table and one consolidated list of decisions, in the format of `naming-audit-2026-10-22.md`.

Reviewed: `docs/adr/0008-layout-data-model-file.md` at Subdivision `ad90af4`, `schemas/layout-model/v3.0.0.json`,
`schemas/layout-model/examples/spcoast.layout.json`, `docs/adr/0008/shape.svg`, `tools/layout_compiler/seams.py` and
`emit.py`, `docs/adr/README.md`; the drawing at Railroad `1dd4190`.

The report is reproduced verbatim below. The architect's disposition of each finding is in the commit that follows
and in ADR 0008 §8.

## 2. UNDEFINED OR AMBIGUOUS TERMS

- **house**: ADR `houses{}`, SCHEMA `house`, 0009 §3.11 "`House`"; GL §11 still retires "house, relay house, shelter, instrument case → bungalow"; the delta (proposed, not applied) reverses this. Authority 1 and authority 3 disagree until the owner edits the glossary.
- **processor** (generic), **transport**, **encoding**, **code line (as an entity keyed by an encoding's name)**, **CMRInet Node**, **anchor**, **route**, **row**: used as keys and prose in ADR and SCHEMA; GL defines only "field processor", "code line" (a path) and "code line type"; all are in the proposed delta or (anchor, route) in neither.
- **OfficeUnit / CTC machine**: ADR §5 and SVG say "OFFICE LOGIC · the CTC machine", `officeUnits{}` names the same thing; GL §3 says prose uses "CTC machine" and `OfficeUnit` is a code alias; ruling 4e says "OfficeUnit not machine". Which word prose uses is unsettled between GL and the ruling.
- **codeline name**: EX keys `AAR Tokens`, `US&S 506` are encoding Values standing in for `Name`; "US&S 506" is also the glossary's code line *type* (GL §6), so instance and type share a name.
- **Seam**: FieldUnit ADR 0005 uses "Seam 1 / Seam 2" (interface layers) and "Seam 1→2 / Seam 2→3 / SEAM-2" (three layers, §4) for different cuts; ADR 0008 cites "FieldUnit ADR 0005" without the section, and the brief's pointer (§4) is the other sense.
- **settings vs params**: see finding 20; which drawn fields are settings is defined only by a compiler blacklist.
- **station**: used for "field station" throughout (ADR, SCHEMA, SVG); GL §11.
- **anchors**: "processors that run the code to interact with this transport" (SCHEMA) vs the set of drawn `Transport-*` instances (compiler, test); see finding 5.

## 3. PENDING DECISIONS FOR THE OWNER

1. Instance polarity override (`Invert`) in the file: default `binding.invert: true`, schema edited before ratification (finding 1).
2. Which drawn fields are settings: default a per-library contract (lint already exists) replaces `NOT_SETTINGS`; `Color` written now (finding 2).
3. Address-less drivers (JMRI): default stay absent until FieldUnit ADR 0005 §8 rules, and §6 says the drivers, not only bindings, are absent (finding 3).
4. Appliance names from `Value` on devices, masts, heads, maintainer calls, columns: default record the exception in 0009 §3.10 and ADR §4.5 via C11; no per-row report (finding 4).
5. Implicit processor/node scope: default sheet-then-ancestors as coded, amended into 0009 §3.12 via C11, with the all-implicit copy (0009 C7) as the test (finding 6).
6. `anchors` semantics: default a FieldUnit's code line implies no anchor; the key is documented as "drawn transport instances", and the §3.12 check "an anchor per connecting processor" is struck or redefined (finding 5).
7. Code-line transport implicit anchor "the machine's processor": default implement it as 0009 says and drop the on-sheet fallback for transports (finding 7).
8. CMRInet Node placed on two sheets: default merge per 0009 §3.9, error on conflicting declarations (finding 8).
9. `provenance.source`: default the project path relative to the Railroad repo plus `git describe`; no netlist hash (finding 10).
10. `provenance.libraries` / `referenceData`: default emit what exists now (pairing-table version, library file versions) rather than promising them in §4.6 (finding 11).
11. Route discriminator: default segment count, stated in §4.5, with two schema patterns (finding 15).
12. `style` shape: default always an array (finding 19).
13. `params` vs `settings` and key casing: default `settings`, keys as drawn (finding 20).
14. `officeUnit.region`: default drop (finding 18).
15. OfficeUnit `Columns`: default strike from the library as derived; else write it (finding 2).
16. `Name` on OfficeUnit and encodings: default library gains `Name` before ratification so no key in the ratified example is a Value (ADR §6 last paragraph).
17. Node and bit `ic`: default written like every driver, one spelling (`CMRInet`) in the library (finding 22).
18. Bit numbering base for the byte check: default 1-based, recorded in 0009 §3.5 (finding 25).
19. Glossary delta: default apply before ratifying 0008, since `houses{}`, `processors{}`, `transports{}` are keys of the public interface and the glossary still retires or lacks them (section 2).
20. `description` keys throughout the schema: default keep for Studio-authored text and say so in §4.3; the compiler never fills them (KiCad `Description` is library text).
21. Vocabulary edits (findings 12, 13, 14, 17, 23, 26, 27): default apply as a rev 4a text pass; no key changes except `$defs.unit`/`$defs.node` names.
