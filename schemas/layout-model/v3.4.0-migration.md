# Layout Data Model File 3.4.0: reference data resolved per entity

The migration note of 3.4.0 (ADR 0008 C8; the owner, 2026-11-13, M1 of the FieldUnit Corporal spike: issue #134). A
minor bump: a 3.3.0 file written by the KiCad importer validates against 3.4.0 but for its `schema` string and the
shape of `provenance.referenceData`, which the writer states, and the `derived` keys below, which any conforming
derivation rebuilds (ADR 0011 §4: `derived` is a cache). A file is not migrated: it is written again by the importer
from the drawing.

## Why

The first consumer in another repository (FieldUnit's generator spike, finding M1) could not read the reference tables:
the file named a date for each and the tables were Python here. The owner ruled that the tables are JSON data files
under the schema folder, the source and not an output; that the derivation resolves them per entity into `derived`, as
it already did for a head's `presents`; and that the file states the selection (the layout's railroad, era and
rulebook) and any explicit override beside the item it overrides, so nothing is re-derived by a reader.

## What changed

| Before | After |
|---|---|
| `provenance.referenceData.<table>`: a version string | `{file, version, schemaVersion}`: the table's data file under `schemas/` (`layout-model/reference/<table>.json`), its provenance date and the schema version it is written to |
| layout (new) | `derived.reference`: each layout-keyed table (`trainOrderInputs`, `policies`) to the row key the layout's `given.Railroad`, `Era` and `Rulebook` resolved to; the selection stays stated in `given` |
| train order face `indications` | kept, and `inputs`: the inputs the face's lever binds, keyed by rank from 1, the most restrictive, each `{input, indication}` (a map: a list in the file is a set, ADR 0008 §4.8); `rest`: the word nothing asserted shows. The board's `Rest` and `Shows.<input>` override the table's words |
| mast `derived.positions.<pin>` (new key) | `shows`: mast indication -> the head word this position shows, the policy row for the rulebook and head count; absent while no row states it (none is shipped yet, #62) |
| JMRI signal mast driver (new) | `derived.aspectNames`: indication -> the aspect name it publishes, for its signal system and its mast's Kind |
| code line `layout.codelines.<name>` (new) | `derived.station` (`house` or `interlocking`) and `derived.tokens` (appliance class -> the office indication templates); the station packets stay uncomputed in the file (the owner, 2026-10-28) |

Rule checks: none added or retired. `tools/layout_model/reference.py` is a loader with no table literal; the
resolution is `tools/layout_model/reference_data.py`; the tables and their schemas are in
`schemas/layout-model/reference/` (its README lists each file's shape).
