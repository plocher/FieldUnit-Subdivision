# Layout Data Model File 3.5.0: a binding states its pin number, direction and sense

This is the migration note of 3.5.0 (the owner, 2026-11-14: ADR 0017 decision 3 and FieldUnit finding M6). It is a
minor bump. The only shape that changes is a device's `relations.bindings`. A file is not migrated: the importer writes
it again from the drawing.

## Why

A binding was a route string only. Three facts that the drawing states were lost, so a reader had to find them again:

- Which side of the wire drives it. The rule check `device.output` needs this.
- The driver pin's number, which FieldUnit's generator needs (finding M6).
- The asserted level. The importer read and checked the device's `Invert` field, but did not write it.

## What changed

| Before | After |
|---|---|
| `relations.bindings.<function>`: a route, or a list of two or more routes | a binding object, or a list of two or more, sorted by route |
| binding (new) | `route`: as before |
| binding (new) | `pinNumber`: the driver pin's number on its symbol, as drawn. It is an integer when it is one. The meaning of the number on a chip is FieldUnit's driver knowledge (for example, MAX7313 A1 to A8 are 1 to 8 and B1 to B8 are 9 to 16). The file does not compute bits. |
| binding (new) | `direction`: the logic's side, from the device pin's KiCad electrical type. `output` means the device pin is typed input and the logic drives it. `input` means the device pin is typed output (or open collector or open emitter) and the logic reads it. Drivers have no direction of their own (the owner, 2026-10-07). This key is absent when the device pin's type states no direction; the importer then reports `binding.direction` at missing. |
| binding (new) | `sense`: `low` for a pin drawn `~{X}`, `high` for a plain name (ADR 0004 D9, ADR 0013 R14). When the device's `Invert` names the pin, the sense is the other one. |

Rule checks: `device.output` now reads `direction`. It reports a binding of an interlocking's device that has direction
`output` and goes to a processor that does not run that interlocking. Its pin table in `derive.py` is gone.
