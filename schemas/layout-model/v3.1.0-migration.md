# Layout Data Model File 3.1.0: the three-maps reshape

The migration note of 3.1.0 (ADR 0008 C8). 3.1.0 is a working schema with no consumer outside this repository, so
it was reshaped in place on 2026-10-27 to ADR 0011 and ADR 0012, with the owner's rulings on
`docs/review/three-maps-mapping-2026-10-27.md`; the `schema` string did not change (ADR 0011 §9). A file written
before the reshape does not validate against it. It is not migrated: it is written again by the KiCad importer
from the drawing, the one source (ADR 0011 §8).

## What every entity and row holds

- `given`: every field a person stated, keyed as drawn, every value a string. Left out: KiCad's housekeeping
  (`Reference`, `Value`, `Footprint`, `Datasheet`, `Description`, `Sheetname`, `Sheetfile`, `ki_*`), `Role`, the
  library's `Pin.*` contract, the key field (it is the map key) and an empty or `~` field. A device row has no
  identity, so its `Name` is in `given`.
- `relations`: every stated connection, each the name it reaches.
- `derived`: what the rules compute; never a copy of a stated value. `provenance.rules` stamps its version.

Readers take meaning from `derived`, then `relations`, then `given` (ADR 0011 §4). Collections and identities (map
keys, a track row's `name` and `id`) stay outside the maps.

| CMRInet Node `ic`, `nodeType`, `inputBytes`, `outputBytes` (integers) | `given.IC`, `.NodeType`, `.InputBytes`, `.OutputBytes` (strings) |
| driver and bit `ic`, `kind` | `given.IC`, `given.Kind` (a bit also `given.Bit`, `given.Node`) |
| code line and I/O encoding `encoding`, `transport`, `processor` | `given.Kind`, `relations.transport`, `relations.processor` |
| processor `board` | `given.Board` (and `given.Kind`) |

| signal joint sides `A`, `B` | `governed`, `approach` (ADR 0012 §8) |
| policy sign `To` or `Track`, NextCP `To` | `track` |

| `track.mileposts[]` | gone: the keys of `geometry.mileposts` |

| device `serves`, `shows` | `derived.serves`, `derived.shows` |

| device `bindings[]` (`function`, `route`, `invert`) | `relations.bindings`, a map from function to route; `invert` gone for `given.Invert` |
| head device (new) | `relations.mast`, its IND wire |
| board lamp in no column (new) | `relations.interlocking`, stated only by the sheet hierarchy |
| OfficeUnit `style`, `processor` | `given.Style`, `relations.processor` |
| column `house`, `interlocking` | `derived.house`, `derived.interlocking`; a column with no `CP Name` has `relations.interlocking` from the sheet hierarchy |
| geometry run `circuit` | `derived.circuit` |
| geometry run `from`, `to` (switch ports only) | `relations.from`, `relations.to`: a switch port or named row pin by name, an unnamed row's pin as `<id>.<side>` |
| geometry marker `kind`, `circuits`, `name`, `ports` | `row`, the track row's `id`; the copies are gone |
| `provenance.compiler` | `provenance.writer`; `provenance.rules` is new (`0.1.0`) |

A track pin's `relations.<side>` (a switch port, a marker's `TC`, every side of a joint, an end or a policy sign)
lists every other track pin on its wire (the owner, 2026-10-27): switch ports, markers' `TC` and named rows' sides by
qualified name (`Luchessa:783.C`, `Luchessa:1SAT.TC`), unnamed rows' sides as `<id>.<side>`, the form a run's ends
use. Version 3.0.0's `ports` listed only switch ports and named pins, so dark track between unnamed rows had no stated
connection; now it has, and the relation is symmetric. A pin never names its own symbol.

Placements (`at`, `glyph`, `rotation`, `mirror`, `heads`), run `points`, `glyphs` and `provenance.libraries` keep
their shape: geometry's only contract with the semantic sections is identity (three-maps D10).

## What the KiCad importer writes now

- Geometry always (ADR 0011 §7): `compile_layout.py` reads the sheets and libraries every time; `--geometry` is gone.
- Every relation by its wire alone (ADR 0012 §4): the one processor on the sheet, the code line in the folder, the
  `Processor` and `Transport` fields and the one CMRInet Node on the sheet no longer resolve anything, and their
  `*.explicit_only`, `*.implicit_only` and `*.disagree` diagnostics are gone. A relation with no wire is reported at
  `missing`. A field that once served as a fallback stays in `given`, read by nothing.
- The derivation (control points, circuits, links, heads, NextCP pairing) still runs inside the importer; its
  results are written to `derived`.
