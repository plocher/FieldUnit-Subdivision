# Layout Data Model File 3.2.0: head positions

The migration note of 3.2.0 (ADR 0008 C8), issue #80 (the owner, 2026-11-04 and 2026-11-09). A minor bump: every
3.1.0 file written by the KiCad importer validates against 3.2.0 but for its `schema` string, since the one thing
removed, a mast's `heads` map of trackplan heads by letter, has not been written since the trackplan head symbols
retired (Railroad PR 20 and 21). A file is not migrated: it is written again by the importer from the drawing.

## What changed

| Before | After |
|---|---|
| device `given.Head`, the head letter | gone: a head has no name and no letter; it is the position its IND is wired to |
| device (new) | `relations.position`: the signal mast device pin (A, B, C top down) a head's IND wire reaches |
| device (new) | `derived.presents`: the head words of the head's model table, by `given.Style` (reference data `head_model`) |
| appliance `heads.<letter>` (a mast's trackplan heads) | gone: a mast's head positions are its field mast device's pins |
| appliance (new) | `derived.positions`: position -> the words it presents (what any head on it presents) |
| appliance (new) | `derived.demand`: the mast's explicit `Indications` list, until #62 derives the demand |
| geometry placement `heads.<letter>` | gone: a trackplan head is no longer drawn |

Rule checks: `head.plan` and `head.vocabulary` are gone; `head.model` (missing), `head.position` (info), `mast.device`
(missing) and `mast.presents` (info) are new; `mast.heads` now compares the mast's name letters with the positions
heads are wired to. Import diagnostics: `head.letter`, `head.duplicate` and `geometry.head` are gone.
